# UI／UX 與介面維護優化評估

日期：2026-09-09。範圍：目前 checkout 的規格與前端程式碼靜態檢視；未操作正式資料、未修改產品程式碼，亦未執行本次瀏覽器驗收。以下為提案，不代表已核准或實作。

## 結論

延續既有明亮 teal、手機底部導覽、平板 rail 與 1024px shell。優先補齊新增、修改與找物品的完整流程，再集中樣式管理與建立元件預覽，讓往後 UI 調整可以快速比較與驗收。

## 已有基礎

004 已有共用確認視窗、Toast、loading/error/empty、搜尋 URL 條件保留、250ms debounce、過期回應保護與 route focus；002/003 已有自動同步、位置詳情及平板版面。這些能力不應列成尚未開發的新需求。

004 tasks 的 T026/T027 尚未勾選：三種 viewport、鍵盤、200% 文字縮放、reduced-motion 與必要對比仍需實際驗收。本次未重新執行，不能視為已通過。

## 使用流程優先順序

| 優先 | 現況與程式證據 | 建議 | 可驗證結果 |
| --- | --- | --- | --- |
| P1 | `features/items/ItemDetailPage.tsx` 顯示基本資料，提供照片、移動及刪除／還原，未提供基本資料編輯入口 | 增加編輯名稱、分類、備註與標籤；沿用權限、歷史及同步規則 | 改名後詳情、搜尋與重新開啟一致；取消不寫入；另驗證雙裝置同步 |
| P1 | `AddItemPage.tsx` 儲存後 `setState(emptyItemForm)`，包含原預選位置一起清空 | 提供「儲存並繼續新增」與「儲存並查看」；連續新增時保留位置／分類，清除前件照片與名稱 | 同箱連續新增三件，不必重選位置，也不殘留前件照片 |
| P1 | 新增表單只有 `beforeunload`，App 以 History API 切頁，未見站內未儲存資料攔截；草稿只在 React state | 加站內離開保護；草稿恢復另訂家庭／使用者隔離、清除及照片保留規則 | 新增到一半切頁再返回，可保留草稿或明確選擇捨棄；不得串到其他家庭 |
| P2 | `HomePage.tsx` 先呈現家庭介紹與統計，再呈現新增／搜尋快捷操作 | 手機縮短介紹，將搜尋入口與新增操作前移；保留既有家庭與同步資訊 | 在 375×812 第一屏可以直接開始找物品或新增 |
| P2 | `SearchPage.tsx` 有篩選與卡片結果，但沒有排序、密度切換；`searchService.ts` 每次讀取家庭集合後篩選 | 先補依名稱／最近更新排序及已套用條件摘要；再依資料量提供清單／卡片切換 | 排序與篩選進詳情後返回仍保留；用大量測試資料量測後才決定是否分頁／虛擬化 |
| P2 | `App.tsx` 設定頁已分組，但各區塊仍同頁展開 | 改成有摘要的設定入口／可展開區塊，例如同步狀態、資料備份、收納選項 | 手機可快速找到目標設定，且收合狀態不掩蓋需要處理的錯誤 |

照片入口可移至新增頁前段，備註／標籤採漸進展開。分類目前屬必填；若改為選填會改變產品資料規則，需在 Specify 明確決定，不能當作純版面調整。

## 讓 UI 調整更方便

1. **完成樣式單一來源**：`styles/global.css` 已有 `--ui-*`，但 `components/ui/controlStyles.ts` 仍直接使用 teal/rose/slate，首頁亦有個別 gradient、radius、shadow。讓共用控制與頁面逐步引用語意變數，涵蓋主色、文字、邊框、focus、圓角、間距及控制尺寸。驗收：只改主題值，所有 primary 按鈕和相關狀態一致改變。
2. **增補常用組合元件**：沿用既有 Button、IconButton、ConfirmDialog、StatusState；補 PageHeader、FormField、SectionCard、StatusBadge，減少各頁重複標題、必填、說明、錯誤與狀態樣式。優先處理本次改動頁面，避免一次重構整個 App。
3. **建立開發用元件預覽頁**：集中展示按鈕、欄位、卡片、Toast、dialog 的正常／loading／error／disabled 狀態，使用固定示範資料且不連正式家庭。可先用輕量開發頁，不必立即加入大型工具。驗收：改樣式後可在一處比較手機／平板與長文字狀態。
4. **分離頁面呈現與資料流程**：頁面目前常同時處理讀取、同步回饋、權限及 JSX。當修改相關頁面時，將資料動作收斂到對應 hook/service，讓版面可用固定資料預覽；不為本次提案全面改路由或資料層。
5. **建立固定視覺驗收情境**：先完成 004 T026/T027，再保存空資料、長名稱、多層位置、大量物品、錯誤、彈窗與鍵盤操作情境。固定 375×812、768×1024、1024×768，加 200% 文字縮放和 reduced-motion。

## 後續系統層優化

- 效能：目前 App 直接匯入各功能頁；可評估路由延遲載入。搜尋仍是集合篩選，先量測 100／1,000／5,000 件情境的輸入、結果與捲動成本，再選擇索引、快取或列表優化；本次沒有實測效能數據。
- 資料信任：備份頁文字明示照片 metadata；應以一般使用者能理解的文字呈現實際包含／未包含的照片內容。完整照片備份及跨裝置媒體能力需獨立確認資料契約與驗收，不應只修改成「完整備份」文案。
- 批次移動、箱子 QR 標籤、借出／數量等可列下一階段候選；涉及新流程或模型，收益須由實際整理情境決定。

## 建議實施順序

先完成 004 視覺驗收，接著針對「物品編輯、連續新增、未儲存保護」建立下一份 Specify → Plan → Tasks。樣式變數整合與元件預覽可規劃為同批支援工作；搜尋與設定重排放第二批。

本次沒有產品變更，故未重跑 typecheck、lint、test、build；不以過往成功紀錄代替本次驗證。
